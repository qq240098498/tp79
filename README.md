# tp79 多语言文案管理平台

一个本地小工具：把产品界面上的文案集中管起来。页面上先登记要支持的语言，再按模块维护一条条文案，每条文案给各个语言分别填译文；键写重了、译文太长、语言代码没登记过，保存时当场就会指出来。

数据全部存在本机的数据文件里，不连数据库，也不调用任何外部服务。

## 技术栈

- 后端：Node.js（>=18）与 Express，前后端同一个进程
- 前端：原生 HTML、CSS 与 JavaScript，页面文件由后端静态目录直接提供，没有构建步骤
- 存储：本地 JSON 文件 `data/db.json`

## 项目结构

tp79/
├── server/
│   ├── index.js        # 服务入口、静态目录、接口路由

## 启动方式

```bash
npm install
npm start
```

启动后打开页面地址：<http://localhost:5079>

端口固定为 `5079`，如需临时改动可在启动前设置环境变量 `PORT`。

## 页面怎么用

1. 顶栏右侧可以填当前操作者，填过之后浏览器会记住，保存文案时会记下是谁改的
2. 语言区列出当前登记的语言，可以看到语言代码、名称、是不是默认语言、是否启用，以及这条语言下已经填了多少条译文
3. 语言区底部可以新增语言，填上代码与名称即可；已有语言可以改名、设为默认、启用或停用、删除
4. 文案区顶部可以按模块筛选、可以按文案键或译文内容搜索，右上角刷新按钮重新拉取一次
5. 点新建文案，填上模块、文案键与各语言的译文就能存下来；列表里点编辑会把这条文案回填到表单，改动保存后列表立刻更新
6. 点删除不会立刻抹掉文案：整条文案连同全部译文先进入**回收站**，保留 7 天，到期自动清除。回收站里能看到这条文案原来的模块与键、全部译文、是谁在什么时候删的，以及距离自动清除还剩多久
7. 回收站里的内容**只读**，不能在回收站里编辑。点“恢复这条文案”即可还原；如果原来的模块与键已经被新的文案占用，页面会当场指出冲突（是哪一条文案、最近由谁更新），操作者可以换一个键再恢复，或者放弃这次恢复
8. 恢复成功后文案回到正常列表，键的旁边会出现“已恢复”标记，鼠标悬停能看到什么时候由谁恢复、恢复后用的是哪个键；回收站下方的“恢复记录”也会留下同样的信息
9. 任何一步不成立时，页面顶部给出说明，并尽量把问题标到对应的输入项上；删除语言与删除文案都会先确认

列表里每种语言单独占一列，空白的格子表示这条文案在这个语言下还没有译文，未登记的格子表示这条文案从来没有写过这种语言。

## 文案键与译文的约定

- 模块名用小写字母开头，后面可以跟数字与短横线，最长 30 个字符
- 文案键形如 `home.banner.title`，由小写字母、数字、下划线与短横线组成，用点号分段，最长 120 个字符；同一个模块下不允许出现重复的键
- 译文最长 200 个字符，允许留空，留空表示这条文案在这个语言下还没有翻译
- 译文里可以写 `{amount}`、`{count}`、`{minutes}` 这样的占位符，由前端在运行时替换成实际取值，平台上原样保存、不做任何处理
- 备注用来写这条文案出现的页面位置，最长 200 个字符
- 操作者名字随保存一起记在文案上，最长 40 个字符，留空按未署名记录

## 数据存储

所有数据写在 `data/db.json`，结构为 `{ "languages": [...], "entries": [...], "trash": [...], "history": [...] }`。落盘时先把内容写进同名临时文件，再用改名的方式替换正式文件，写入过程中断也不会把数据文件写坏；文件缺失或内容损坏时会自动回落到初始数据。

- `trash` 是回收站：删除的文案整条搬进来，额外记录删除人 `deletedBy`、删除时间 `deletedAt` 与自动清除时间 `expireAt`（删除后 7 天）。每次读取数据都会剔除已到期的条目，并在下次落盘时物理清除
- `history` 是恢复记录：记下恢复时间、操作者、恢复后使用的键以及删除前的原键（换键恢复时两者不同），最多保留最近 200 条

## 接口一览

| 方法   | 路径                   | 说明                                         |
| ------ | ---------------------- | -------------------------------------------- |
| GET    | /api/health            | 服务状态检查                                 |
| GET    | /api/languages         | 语言清单，附带每种语言已填译文条数           |
| POST   | /api/languages         | 新增语言                                     |
| PATCH  | /api/languages/:code   | 修改语言的名称、启用状态或默认标记           |
| DELETE | /api/languages/:code   | 删除语言                                     |
| GET    | /api/entries           | 文案列表，支持按模块与关键词筛选，附带最近恢复记录 `history` |
| POST   | /api/entries           | 新增文案                                     |
| GET    | /api/entries/:id       | 查看单条文案                                 |
| PATCH  | /api/entries/:id       | 修改文案                                     |
| DELETE | /api/entries/:id       | 删除文案（软删除：整条移入回收站，请求体可带 `operator`） |
| GET    | /api/trash             | 回收站清单（已到期的不返回）                 |
| POST   | /api/trash/:id/restore | 恢复回收站条目；请求体可带 `operator` 与 `key`（换键恢复）。原模块下该键已被占用时返回 409 与冲突详情 `error.conflict` |

冲突时的响应体示例：

```json
{
  "error": {
    "code": "RESTORE_KEY_CONFLICT",
    "message": "模块 home 下的键 home.banner.title 已经被新文案占用……",
    "field": "key",
    "conflict": {
      "module": "home",
      "requestedKey": "home.banner.title",
      "occupiedBy": { "id": "…", "key": "home.banner.title", "updatedBy": "测试员乙", "updatedAt": "…" }
    }
  }
}
```

接口出错时统一返回 `{ "error": { "code": "...", "message": "...", "field": "..." } }`，其中 `field` 用于让页面把问题标到具体的输入项上。
