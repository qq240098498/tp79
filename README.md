# tp79 多语言文案管理平台

一个本地小工具：把产品界面上的文案集中管起来。页面上先登记要支持的语言，再按模块维护一条条文案，每条文案给各个语言分别填译文；键写重了、译文太长、语言代码没登记过，保存时当场就会指出来。

删除文案不会立刻消失，而是先进回收站，保留 30 天，期间可以随时恢复；原来的模块与键已经被新文案占用时，恢复会被当场拦下，说明冲突在哪，可以换一个键再恢复或者放弃。

数据全部存在本机的数据文件里，不连数据库，也不调用任何外部服务。

## 技术栈

- 后端：Node.js（>=18）与 Express，前后端同一个进程
- 前端：原生 HTML、CSS 与 JavaScript，页面文件由后端静态目录直接提供，没有构建步骤
- 存储：本地 JSON 文件 `data/db.json`

## 启动方式

```bash
npm install
npm start
```

启动后打开页面地址：<http://localhost:5079>

端口固定为 `5079`，如需临时改动可在启动前设置环境变量 `PORT`。

## 页面怎么用

1. 顶栏右侧可以填当前操作者，填过之后浏览器会记住，保存、删除与恢复时都会记下是谁操作的
2. 语言区列出当前登记的语言，可以看到语言代码、名称、是不是默认语言、是否启用，以及这条语言下已经填了多少条译文
3. 语言区底部可以新增语言，填上代码与名称即可；已有语言可以改名、设为默认、启用或停用、删除
4. 文案区顶部可以按模块筛选、可以按文案键或译文内容搜索，右上角刷新按钮重新拉取一次
5. 点新建文案，填上模块、文案键与各语言的译文就能存下来；列表里点编辑会把这条文案回填到表单，改动保存后列表立刻更新
6. 点删除不会立刻抹掉，文案会先进入回收站；文案区右上角的「回收站」按钮带条数角标，打开后能看到回收站里的全部内容
7. 任何一步不成立时，页面顶部给出说明，并尽量把问题标到对应的输入项上；删除语言与移入回收站都会先确认

列表里每种语言单独占一列，空白的格子表示这条文案在这个语言下还没有译文，未登记的格子表示这条文案从来没有写过这种语言。

## 回收站与恢复

- 删除文案即移入回收站，保留 **30 天**，到期后下一次读取数据时自动清除，无需手工清理
- 回收站只读：可以查看但不能编辑。每条都能看到原来的模块与键、删除当时各语言的全部译文（连后来被删掉的语言那一格也保留并标注）、是谁在什么时候删的，以及距离自动清除还剩多久，剩余时间不足一天会标红
- 点「恢复」先尝试回到原来的模块与键。如果原位置已经被新的文案占用，会当场拒绝并指出冲突双方（现有文案的模块、键与编号），操作者可以在弹窗里换一个模块或键再恢复，也可以放弃这次恢复；换新键后仍冲突会继续提示
- 恢复成功后文案回到正常列表，列表新增「恢复记录」一列，能看到每次恢复的时间、由谁恢复、恢复后实际使用的键；换键恢复时还会附上原来的模块与键
- 同一条文案被删除、恢复、再删除时，历次恢复记录会一直跟着这条文案保留

## 文案键与译文的约定

- 模块名用小写字母开头，后面可以跟数字与短横线，最长 30 个字符
- 文案键形如 `home.banner.title`，由小写字母、数字、下划线与短横线组成，用点号分段，最长 120 个字符；同一个模块下不允许出现重复的键
- 译文最长 200 个字符，允许留空，留空表示这条文案在这个语言下还没有翻译
- 译文里可以写 `{amount}`、`{count}`、`{minutes}` 这样的占位符，由前端在运行时替换成实际取值，平台上原样保存、不做任何处理
- 备注用来写这条文案出现的页面位置，最长 200 个字符
- 操作者名字随保存一起记在文案上，最长 40 个字符，留空按未署名记录

## 数据存储

所有数据写在 `data/db.json`，结构为 `{ "languages": [...], "entries": [...], "trash": [...] }`。回收站条目除文案内容外还带 `deletedBy`、`deletedAt`、`expiresAt` 与历次 `restoreRecords`；正常文案上的 `restoreRecords` 记录每次恢复的原键、新键、操作者与时间。落盘时先把内容写进同名临时文件，再用改名的方式替换正式文件，写入过程中断也不会把数据文件写坏；文件缺失或内容损坏时会自动回落到初始数据。读取数据时会顺手清掉回收站里已过保留期的条目并落盘。

## 接口一览

| 方法   | 路径                   | 说明                                         |
| ------ | ---------------------- | -------------------------------------------- |
| GET    | /api/health            | 服务状态检查                                 |
| GET    | /api/languages         | 语言清单，附带每种语言已填译文条数           |
| POST   | /api/languages         | 新增语言                                     |
| PATCH  | /api/languages/:code   | 修改语言的名称、启用状态或默认标记           |
| DELETE | /api/languages/:code   | 删除语言                                     |
| GET    | /api/entries           | 文案列表，支持按模块与关键词筛选             |
| POST   | /api/entries           | 新增文案                                     |
| GET    | /api/entries/:id       | 查看单条文案                                 |
| PATCH  | /api/entries/:id       | 修改文案                                     |
| DELETE | /api/entries/:id       | 删除文案（移入回收站，请求体可带 operator）  |
| GET    | /api/trash             | 回收站列表，支持按模块与关键词筛选，带总条数、保留时长与服务端时间 |
| POST   | /api/trash/:id/restore | 恢复回收站文案，可在请求体指定新的 module/key；键冲突时返回 409 与冲突双方 |

接口出错时统一返回 `{ "error": { "code": "...", "message": "...", "field": "...", "details": {...} } }`，其中 `field` 用于让页面把问题标到具体的输入项上；恢复冲突时 `details` 里给出 `origin`、`requested` 与 `conflict` 三方的模块、键与编号。
